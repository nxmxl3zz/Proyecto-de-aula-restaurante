| **ESPECIFICACIONES DEL PROYECTO** |  |  |  |  |  |  |
| • El proyecto de aula se realizará en parejas, siguiendo los parámetros: <br>**Procedimientos**:<br>El desarrollo del proyecto de aula del momento uno (1), tiene como propósito evidenciar lo que los estudiantes conocen, comprenden y/o son capaces de hacer en el ciclo básico de ingeniería, mediante la construcción de un producto de software, que solucione una problemática identificada y formulada por el estudiante.<br>El producto de software a construir debe cumplir con los siguientes requisitos:<br>• Entorno gráfico (Implementación de interfaces gráficas de usuario). <br>• Persistencia en archivos (Implementación de operaciones CRUD en archivos) <br>• Uso general de técnicas y/o mecanismos de programación orientada a objetos: (Abstracción, encapsulamiento, sobrecarga, relaciones entre clases, herencia, polimorfismo, colecciones de objetos, manejo de excepciones) <br>• Implementación de arquitectura por capas (entidades, datos, servicios, presentación).<br>**El código fuente debe cumplir con los siguientes requisitos:** <br>• Aplicación de estándares para la nomenclatura de paquetes, clases, métodos y atributos.<br>• Cada clase del código debe ir debidamente documentado<br>• Aplicar buenas prácticas de escritura de código <br>**FASES DEL PROYECTO DE AULA:**<br>**Fase No 1: Identificación, formulación, comprensión y especificación del problema.s**<br>a) **Identificación y formulación del problema o necesidad**: los estudiantes deberán identificar una problemática o necesidad real asociada al manejo y gestión de información, y con ello, formular el problema, sus causas, consecuencias y área de aplicación, así: <br>**PROBLEMA O NECESIDAD** / **CAUSAS** / **CONSECUENCIAS** / **ÁREA DE APLICACIÓN**<br>Describa el problema o necesidad central resaltando la forma como se desarrolla el proceso o actividad que presenta la problemática. /  /  / El proyecto puede dar solución a un problema enmarcado dentro de una o más áreas, por ejemplo:<br>• Medio ambiente<br>• Salud y bienestar social<br>• Actividades agropecuaria y ganaderas<br>• Actividades comerciales y desarrollo económico<br>• Educación <br>• Otros<br>b) **Estado del arte / Vigilancia tecnológica** <br>Realice una revisión en diferentes fuentes sobre soluciones que resuelvan el problema identificado. Enumérelos y describa funciones . Recuerde citar las fuentes.<br>**N** / **Funcionalidades** / **Nombre Proyecto 1** / **Nombre Proyecto 2** / **Nombre Proyecto 3** / **Nombre Proyecto 4**<br>**1** / Funcionalidad 1 /  /  /  / <br>**2** / Funcionalidad 2 /  /  /  / <br>**3** / Funcionalidad 3 /  /  /  / <br> / Funcionalidad 4 /  /  /  / <br>c) **Descripción de la solución:** Se debe describir el alcance, el qué, el porqué y el para qué de la solución propuesta con un factor diferenciador, además, con base en la problemática abordada, los estudiantes deberán formular los requerimientos funcionales de su aplicación, incluyendo control de acceso.<br>d) **Diseño preliminar:**  Teniendo en cuenta que, en esta etapa los estudiantes deben tener claridad del contexto de desarrollo de la problemática, así como también los requerimientos funcionales de su aplicación, deberán entonces presentar un modelo computacional basado en UML preliminar de su solución (diseño preliminar diagrama de clases), cumpliendo con los siguientes requisitos:<br>• **Identificar entidades.**  Presentar un listado de las clases identificadas en el problema y que harán parte de su solución, es decir, las clases que implementarán. Así mismo, deberán presentar una descripción breve de cada una de ellas.<br>• **Diseño UML.** Elaborar el diagrama UML para cada una de las clases incluidas en el inciso anterior, que incluya el nombre, y los atributos. Los métodos son opcionales.<br>• **Diagrama de clases preliminar.** Identificar las posibles relaciones entre clases (agregación y composición) que considere, y posteriormente elaborar un diagrama general de clases, que incluya todas las clases modeladas y sus relaciones. Tanto las clases como las relaciones deben respetar la notación UML.<br>• **Implementación de código.** Deberán mostrar un avance en el desarrollo del programa. Específicamente, la implementación de las clases incluidas en el diagrama de clases, prueba y funcionamiento de objetos de cada una de ellas**.**<br>**Fase No 2: Definición de la arquitectura del proyecto**<br>• Diagrama de clases mejorado (redefinición de clases y atributos, si es necesario), incluir herencia, clases abstractas, e interfaces.<br>• Definición de la arquitectura (Diagrama de paquetes)<br>• Diseño preliminar de interfaces gráficas de usuario (mockup o wireframe)<br>• Funcionalidad completa del aplicativo en modo consola y colecciones de objetos (ArrayList)<br>  **Fase No 3: Desarrollo del producto final de software**<br>• Software final funcional (proyecto implementado con todas las funcionalidades, interfaces gráficas de usuario GUI y Persistencia en archivos)<br>**Documento de la entrega:**  Se debe entregar un documento en pdf con la siguiente estructura: <br>**Preliminares:** <br>• Hoja de presentación y tabla de contenidos.<br>**Desarrollo del tema:**<br>• 1. Planteamiento del problema<br>• 2. Descripción de la solución<br>• 3. Diseño preliminar<br>• 4. Arquitectura del proyecto (diagrama de paquetes)<br>• 5. Diseño de GUI (interfaces gráficas de usuario)<br>• 6. Código desarrollado (Funcionalidad completa del aplicativo en modo consola y colecciones de objetos -ArrayList).<br>**Sustentación**: Todos los integrantes del grupo deben sustentar el documento elaborado y realizar la demostración del aplicativo desarrollado. Máximo 10 minutos de pitch.<br>**Peso evaluativo**: 5 |  |  |  |  |  |  |
